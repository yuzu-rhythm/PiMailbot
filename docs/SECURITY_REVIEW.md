# 公開内容とセキュリティ点検

## 公開範囲

開発環境とは別のディレクトリに、明示したファイルだけをコピーしました。元のGit履歴は継承せず、公開用に新しい履歴を作ります。運用中のPiや開発環境の設定を公開用に書き換える作業は行いません。

- 含む：アプリケーションソース、既存テスト、設定補助、systemd例、空の設定雛形、設計資料、架空データのデモ。
- 含まない：実メール、実カレンダー、実Todoistデータ、画像、SQLite/WAL/SHM、ログ、バックアップ、セッション、Cookie、APIキー、OAuthファイル、`.env.local`、SSH鍵、venv、ビルド成果物。
- 開発用README、端末修復手順、時系列の運用記録、個人環境の一括デプロイスクリプトはコピーせず、公開向け資料を作成しました。

`EXPORT_MANIFEST.json` はコピー元の内容ハッシュと、公開コピー側のハッシュを記録します。元の絶対パスや秘密値は記録しません。公開用の追加資料・デモは別途作成しています。

## 点検内容

1. 公開候補の全テキストを、個人メールアドレス・ローカルパス・プライベートIP・長いDiscord ID・秘密鍵・APIトークンの形式で検索。
2. 開発環境に保存された認証関連値との一致をローカルで比較。値そのものや対応表は公開しない。
3. テストの実サーバーIDを架空値へ置換。残る長いIDはこの架空フィクスチャであることを確認。
4. example.invalidのメール、localhost、Google/Discord/Todoist等の公開APIエンドポイント、Linux配置例を、個人設定と区別して確認。
5. 画像は新規ブラウザプロファイルと架空データのみで作成し、目視確認。
6. ステージするファイルと新しいGit履歴を点検し、ランタイム・ビルド生成物の混入を防止。

この点検は秘密情報の露出を減らすための公開前確認で、アプリケーションの包括的なセキュリティ認証ではありません。

## 利用時の注意

許可対象は既定拒否です。認証情報はGit除外したファイルへ保存し、親0700・ファイル0600を使用します。Gmail変更や外部連携は明示的に有効化し、最初は自分の検証用アカウントで確認してください。

ダッシュボードは個人のローカル表示用です。外部公開用のユーザー認証は実装していません。実データを返すサービスをそのままインターネットへ公開しないでください。
